2. `git merge -s ours fdbe63cf96` → **`b97b52f1`**: переписанный v1.77.0 записан как уже влитый,

3. merge-base(HEAD, v1.79.0) стал `fdbe63cf96` (единственный), вместо старого `bc0ab8b9`.
4. `git merge v1.79.0` → **`166a1564`**: в трёхстороннее слияние попали только 27 коммитов

**На будущее.** Следующие слияния апстрима — обычные, merge-base теперь их. `git fetch upstream
--tags` будет отказываться двигать v1.76.1/v1.77.0 («would clobber existing tag») — это ожидаемо,
**не форсить**: на старые хэши ссылаются прошлые передачи и леджер. Если апстрим перепишет историю
снова — та же процедура: сверить деревья, затем `-s ours` на новый тег.

## 4. Брендинг, манифест, `index.html`

* В `index.html` добавлена `<link rel="manifest" href="__APP_MANIFEST__">`. Плейсхолдер
  подставляет на сборке тот же `vite-plugins/brandingHtml` из `VITE_API_URL` (пусто → `/api`).
  В `dist/index.html` после `npm run build` плейсхолдеров не осталось, манифест —
  `/api/cabinet/branding/manifest.webmanifest`, фавикон — `/api/cabinet/branding/favicon`.
  Имя и логотип «Дон Батон» по-прежнему приезжают от бота в рантайме, поэтому `stage-cabinet.sh`
  без build-args даёт корректный бандл, как и в 1.77.0.
* Манифест с того же сайта кабинет больше не подменяет `data:`-манифестом
  (`hasSameOriginManifest()`); у нас API на том же домене — значит, Chrome на Android будет ставить
  **настоящее приложение**, а не ярлык. Ручки бота (`manifest.webmanifest`,
  `app-icon/{size}.png`, `app-icon/maskable/{size}.png`) есть в боевом боте с 4.13.0; `base` по
  умолчанию `/`, что для `lk.donbaton.tech` верно. Иконка без рамки для плиточного логотипа — с
  ботом 4.15.0.
* Хостовый nginx: по локальной копии `local-ops/_claude/stack-dbcore/nginx/snippets/cabinet-locations.conf`
  (10.09) `/api/` описан как `location ^~ /api/` — regex-локации не перехватят `…/app-icon/*.png`,
  всё уйдёт в бота. Копия старая — проверить `curl` после выкладки (раздел 9).

### Требования форка к нашему боту — не изменились

## 6. Решения за владельцем

### 6.1 🔴 Простой вид — не включать

`TariffPickerLite`, `SubscriptionLite`, `DashboardLite` про сетевые категории не знают: нет вкладок
Wi-Fi / Wi-Fi + LTE / архив и дефолта `wifi_lte` (всё одним списком), нет замков (запертые тарифы
кликабельны → отказ бота), сеть → сеть идёт в пропорциональную смену (бот отвечает
`network_purchase_only`, форма смены передаёт в покупку — лишний шаг), вместо LTE-гигабайт и
периода — `traffic_limit_label`, LTE-квоты не видно, сетевой подписке предлагается докупка
устройств, пакет трафика — по `traffic_limit_gb > 0`, а не `canBuyTraffic`.

Деньги это не ломает: бот форка сам отказывает сетевым подпискам в докупке устройств
(`devices.py`) и в пропорциональной смене сетевых тарифов. Ломается путь клиента.

Выключатель — «Админка → Настройки → Брендинг → «Простой вид кабинета»», раздел открывается
**по умолчанию**, право бота `settings:edit` (у роли «Маркетинг» его нет). Работает уже на боте
4.13.0 — риск появляется в момент выкладки кабинета. Перед выкладкой проверить, что ключ не
включён (раздел 9). Если простой вид нужен — отдельная задача форка (научить три экрана
категориям или скрыть выключатель).

### 6.2 🟡 «Старые» подписки без тарифа на боте ≥ 4.14.0

Бот 4.14+ (`app/utils/legacy_subscription.py`) ставит `requires_tariff_selection` любой платной
не-триальной подписке с `tariff_id IS NULL` в режиме тарифов, отдаёт ей пустые пакеты трафика и
`400 tariff_required` на докупку устройств и трафика (`devices.py`, `traffic.py`). По леджеру на
момент переезда (~04.09): **21 активная подписка без тарифа** («безлимиты и нераскладываемые
объёмы», ручной разбор) и 1047 старых, в основном давно истёкших. С тех пор не пересчитывалось.

Что **уже так** и не меняется этим слиянием:

* автоплатёж таким подпискам не работает и в боевом боте (`monitoring_service`: «Пропускаем
  классическую подписку без тарифа в autopay (tariff mode)», клиенту — разовое уведомление);
  1.78 лишь прячет вводящий в заблуждение тумблер;
* замок форка «архив ↔ сеть при живой подписке» действовал на них и в 1.77.0 (он стоял раньше
  «Выбрать для продления»): без `network_category` сетевые тарифы заперты до конца срока.

Что **новое** с ботом 4.15.0 и кабинетом этого слияния:

* без `network_category`: нет докупок (кабинет прячет, бот отказывает), кнопка продления стала
  «Перейти на тариф» (витрина с `subscriptionId`), заголовок «Без тарифа», пояснения «Подписка
  куплена до появления тарифов» больше нет. В витрине доступны только тарифы архивной группы,
  если такие в продаже; если нет — до конца срока купить нечего (как и сейчас, но теперь и без
  докупок);
* с `network_category`: другие сетевые тарифы — «Перейти», обычная покупка; докупка LTE-пакета
  пропадает (бот: `tariff_required`) — **это прямая потеря для LTE-клиентов, если такие есть**;
* с `renewal_requires_expiry`: пояснение форка вместо кнопки, витрина заперта (как сейчас).

Нужно до бота 4.15.0: посчитать активные платные подписки с `tariff_id IS NULL` в разрезе
`network_category` и `renewal_requires_expiry`, и решить: (а) принять как есть; (б) в боте форка
не считать «старыми» подписки с `network_category` — кабинету тогда менять ничего не нужно: все
его ветки завязаны на флаг `requires_tariff_selection`, и LTE-пакет вернётся сам; (в) для
«старых» подписок без категории разрешить переход на сеть — в боте и одновременно снять замок
архив → сеть для `needsTariff` в кабинете (одна правка кабинета без бота даст отказ бота).
Координировать с исполнителем слияния бота 4.15.0; что бот 4.14+ показывает таким клиентам в
самом Telegram (меню `keyboards/inline.py`, `handlers/subscription/*` тоже смотрят на
`is_legacy_subscription`) — вопрос его передачи.

### 6.3 Мелкое

* Роли «Маркетинг» (`admin_roles.id=6`) права `user_reminders:*` не выданы — на боте 4.15.0
  «Напоминания» увидят только полные админы. Выдавать ли — решение владельца.
* «Выйти» пропадёт в Telegram Mini App — изменение апстрима, для Mini App вход и так через
  Telegram.
